# Poncho v0.3.0 — Plan

> **Goal.** Make Poncho-NES capable of running converted iNES games faithfully at its native 1024×960 resolution, with Contra (UxROM, CHR-RAM, vertical scroll, sprite-0 hit, 8×16 sprites) as the lead validation game.

## Architectural principle

Two consoles, fully independent:

| Layer | Status |
|---|---|
| 2A03 CPU | shared design (same source, both consoles) |
| 2A03 APU | shared design |
| PPU | independent: 2C02 vs 2C02-Ultra |
| Mapper | independent: iNES mappers vs PonchoMapper variants |
| ROM format | independent: iNES vs PonchoROM |

**No runtime compat layer.** The PpuUltra has multiple *native* render/OAM/CHR modes. The PonchoROM format declares which mode each cartridge uses. The conversion tool is the only place where iNES → PonchoROM translation happens, and it's offline.

Two `.poncho` shapes are first-class:

- **Upscaled mode** (`flags.upscaledMode = 1`) — converted iNES games. CHR is 8×8 2bpp, OAM is 4-byte sprites at 8-bit coords. PpuUltra renders each NES pixel as a 4×4 block. PRG runs verbatim.
- **Native mode** (`flags.upscaledMode = 0`) — hand-crafted or art-replaced games. CHR is 32×32 8bpp, OAM is 8-byte sprites at 16-bit coords. PpuUltra renders pixel-for-pixel.

A converted ROM starts in upscaled mode and can be incrementally re-authored toward native mode (replace one CHR bank, then OAM convention, then palette …). The format supports both endpoints and any mid-state.

## Phases

Runtime first, in dependency order. Each phase ends with synthetic `.poncho` test ROMs that exercise the new feature — the converter only shows up after the runtime is fully capable.

### Track A — Runtime

| # | Phase | Scope | Verification | Effort | Status |
|---|---|---|---|---|---|
| 1 | Format extension | `flags.upscaledMode` bit; plumb `chrRamKb`; `mapperSubmode` = banking-variant selector + boot mirroring | round-trip writer/parser tests; CHR-RAM allocates writable buffer | 1d | ✅ **done** |
| 2 | PonchoMapper banking variants — NROM-style + UxROM-style | UxROM-style: 16 KB switchable @ $8000-$BFFF, fixed last bank @ $C000-$FFFF | synth ROM bank-switches, reads back distinct banks | 2d | ✅ **done** |
| 3 | Multi-nametable + mirroring | $2400/$2800/$2C00 + horizontal/vertical/single/four-screen, driven by `mapper.mirroring()` | synth ROM with vertical mirror writes distinct content to NT0/NT1, scrolls X=256 | 3-4d | ✅ **done** |
| 4 | Upscaled-CHR render path | PpuUltra renders 8×8 2bpp tiles as 4×4 blocks; CHR fetched via `mapper.ppuRead`; CHR-RAM via $2007 | synth ROM uploads NES-format tile via $2007, sees 4×4-block render | 3-4d | ✅ **done** |
| 5 | Upscaled-OAM render path | $4014 = 256-byte DMA; 4-byte NES sprites at 8-bit coords; ×4 scale at render | synth ROM places NES sprite at (8,16) tile 0, sees 32×32 colored block at Poncho (32,64) | 3-4d | planned |
| 6 | Sprite-0 hit + 8×16 sprites | PPUSTATUS bit 6 at dot of collision; PPUCTRL bit 5 → 32×64 sprites | synth ROMs for each | 3-5d | planned |
| 7 | Per-scanline mid-frame state | Render scanline-by-scanline so PPUMASK/scroll/palette mid-frame writes apply to correct line ranges | synth ROM split-screen scroll change | 5-7d | planned |
| 8 | Other mapper variants | MMC1, CNROM, MMC3 (incl. IRQ), AxROM | synth ROM per variant | 4-7d | planned |

## Dependencies

```
Phase 1 (format) ──► Phase 2 (mapper variants)
                 ├─► Phase 4 (CHR-RAM)
                 └─► Phase 9 (converter)

Phase 2 ────► Phase 3 (mirroring) ──► Phase 7 (scanline)
         └──► Phase 4 (CHR via mapper)

Phase 3 ────► Phase 7

Phase 4 ────► Phase 5 (OAM)

Phase 5 ────► Phase 6 (sprite-0, 8×16) ──► Phase 7

Phases 1-7 + Phase 8(UxROM) + Phase 9 → Phase 10 (Contra MVP)

Phase 10 ────► Phase 11 (other games) ──► Phase 12 (regression)
```

## Total estimate

- **Runtime track**: ~24-37 days (~5-7 weeks)
- **Converter track**: ~12-20 days, mostly overlapping with runtime polish
- **MVP (Contra playable)**: ~4 weeks

## Risks

- **Phase 7** (scanline-grained PpuUltra refactor) is the highest-risk single phase; tests for mid-frame effects need careful design.
- **Game-specific quirks** (Phase 11) almost always uncover spec gaps — budget extra time per game for runtime-side fixes.
- **MMC3 IRQ counter** (Phase 8) has historically been the most-failed sub-test; expect 2-3 days alone for IRQ accuracy.

## Definition of done

- All synthetic test ROMs from each phase pass.
- Contra plays through level 1 with no visible artifacts (Phase 10).
- The headless regression suite (Phase 12) passes for at least 6 curated games.
- `docs/poncho-rom.md`, `docs/consoles.md`, `docs/architecture.md`, `CHANGELOG.md`, `ROADMAP.md` are all updated to reflect the shipped work.
