# Poncho v0.5.0 — Plan

> **Goal.** Validate the v0.3 runtime + v0.4 AI converter against a wide library of converted iNES games, and lock results into a regression suite so future runtime changes don't silently regress.

## Context

- v0.3 shipped a complete Poncho-NES runtime + a verbatim iNES → upscaled-mode `.poncho` converter. Contra plays at 99–100% pixel match against the reference NES emulator.
- v0.4 ships AI-driven CHR upscaling (nanobanana / Gemini 2.5 Flash Image), with both pre-conversion (CHR-ROM games) and runtime-async (CHR-RAM games) pipelines.
- v0.5 is **all about coverage**: prove the stack works on a range of titles, build the harness that protects future work.

## Phases

### Phase 1 — Game-by-game validation

Boot each title through the converter, observe what works, fix what breaks. Each game gets a frame-N screenshot baseline + a targeted issue list. Order is roughly easiest-first:

| Game | Mapper | Notable features needed |
|---|---|---|
| **Donkey Kong** | NROM | basic CHR-ROM render |
| **Super Mario Bros.** | NROM | scrolling + sprite-0 hit (status bar) |
| **Castlevania** | UxROM | sibling of Contra — likely works out of the box |
| **Mega Man 2** | MMC1 | CHR-RAM, mirroring control, PRG mode swap |
| **Battletoads** | AxROM | single-screen mirror toggle, heavy sprite usage |
| **Super Mario Bros. 3** | MMC3 | scanline IRQ counter accuracy stress |
| **Final Fantasy / Zelda** | MMC1 | battery-backed save (deferred unless trivial) |

Bug fixes that surface during validation are backported as point releases (`0.5.x`). The runtime is feature-complete; this is purely about polishing rough edges against real software.

**Effort.** ~5–10 days, with some games potentially exposing runtime quirks that loop back to a small PpuUltra/PonchoMapper fix.

### Phase 2 — Headless regression harness

`npm run test:games` — CI-friendly per-game runner:

1. Reads `tests/conversion/games.json` (per-game: input path, baseline screenshot, frame-N to capture, optional input scripts to advance past title)
2. Converts iNES → `.poncho` in memory
3. Runs N frames in PonchoNes (with optional scripted input)
4. PNG-diffs against baseline
5. Optionally captures audio buffer for diff

Output: per-game pass/fail with diff-region coordinates if mismatched. Locks in known-good state.

**Effort.** ~2–3 days.

### Phase 3 — Polish + release packaging

- Update `docs/consoles.md` with the verified game list
- Update `README.md` with screenshots from at least 3 working games
- Verify the web shell + Convert button work end-to-end with each curated game
- Tag v0.5.0

**Effort.** ~2–3 days.

## Deferred (not in v0.5)

These items appear in the broader roadmap (`ROADMAP.md`) but aren't v0.5 work:

- Save states / battery SRAM persistence (touches many mappers)
- MMC2 / MMC5 / VRC6 / Color Dreams family mappers
- DMC DMA CPU stall (per [`DEFERRED.md`](../DEFERRED.md))
- Sub-cycle bus alignment for blargg-perfect timing
- Native-mode authoring tools (handcrafted Poncho games)

## Total estimate

~2–3 weeks calendar time, primarily gated on Phase 1's per-game debugging cycles.
